# 00 环境与工作流

三个环境，各做各的事。原则：**不花钱、不占机器的事都在本地做完；上机只负责跑。**

| 环境 | 用途 | 不在这里做 |
|---|---|---|
| 本地 WSL（`/home/wjq`） | 读源码、写服务和脚本、整理结果、写笔记、刷题 | 跑模型（没有 GPU / NPU） |
| AutoDL 4090 D | 项目 A 的全部实验；vLLM 源码阶段的验证实验 | 调试协议、写脚本 |
| 远程 A3（910C） | 项目 B 的全部实验 | 长时间读代码 |

## 一、代码和结果怎么组织

### 仓库

- **项目 A**：`virtuosojq/nano-vllm`，在 `back` 分支上继续开发。建议新开 `bench-v2` 分支做评测重做，完成后合回 `back`。
- **项目 B**：新建一个自己的仓库（例如 `virtuosojq/ascend-moe-bench`），只放启动脚本、压测脚本、结果 JSON、分析笔记。**不要放任何公司内部代码或数据。**
- 源码阅读：vLLM `v0.31.0` 和本地 `/home/wjq/tmp/vllm-ascend` 只读，不提交。

### 结果文件约定

每次实验产出一个 JSON，文件名带上平台、日期、场景、引擎：

```
results/v2/<platform>/<YYYYMMDD>_<scenario>_<engine>[_<variant>].json
例：results/v2/4090d/20261110_S3-sharegpt-rate4_vllm.json
    results/v2/4090d/20261110_S3-sharegpt-rate4_nano_hybrid.json
    results/v2/a3/20261124_S1-random1024x128-inf_vllmascend_w8a8-tp1.json
```

每个目录放一个 `env.json`，开机后第一件事就生成它：

- 硬件：GPU/NPU 型号、数量、显存
- 软件：驱动版本、CUDA / CANN 版本、torch / torch_npu 版本、vLLM / vllm-ascend 版本
- 代码：nano-vllm 的 commit hash
- 模型：路径、dtype、量化方式

对比的前提是 `env.json` 一致。型号或版本变了，整组重测。

## 二、AutoDL 4090 D

### 选机和开机

- 固定选 **RTX 4090 D**，单卡即可。下单前确认型号，开机后 `nvidia-smi` 再确认一次。
- AutoDL 实例绑定在某台物理机上，下次开机时那台机器的卡可能被别人占了。所以环境配好后**保存镜像**；卡被占时用镜像在同型号的其他机器上新开实例。

### 省钱流程

1. **无卡模式开机**：装环境、下模型、下数据集都用无卡模式，价格低很多。
2. **模型和数据放数据盘** `/root/autodl-tmp`，系统盘空间小，而且镜像里不要塞大文件。
3. **网络加速**：`source /etc/network_turbo`（AutoDL 学术资源加速）；Hugging Face 用 `export HF_ENDPOINT=https://hf-mirror.com`；模型优先从 ModelScope 下。
4. **开卡前脚本必须写完并在本地检查过**。开卡后只跑一个总控脚本，跑完把结果拉回本地，立刻关机。
5. 用 `tmux` 或 `nohup` 跑长任务，断开 SSH 不中断。

### 两个 conda 环境

nano-vllm 依赖 `torch 2.5.1 + cu124 + flash-attn`，vLLM 会装自己锁定的 torch 版本，两者放一起会冲突。

| 环境名 | 装什么 | 用途 |
|---|---|---|
| `nano` | torch 2.5.1、flash-attn、transformers、fastapi、uvicorn、nano-vllm（`pip install -e .`） | 起 nano-vllm 服务 |
| `vllm` | vLLM `v0.31.0`（装不上就选能装上的最近版本，并记进 `env.json`）、lm-eval | 起 vLLM 服务；**两侧共用的压测客户端 `vllm bench serve` 也在这个环境里跑** |

压测客户端必须是同一个环境、同一个版本，这是两边指标口径一致的前提。

### 需要准备的模型和数据

```bash
# 模型（ModelScope）
modelscope download --model Qwen/Qwen3-0.6B --local_dir /root/autodl-tmp/models/Qwen3-0.6B
modelscope download --model Qwen/Qwen3-4B   --local_dir /root/autodl-tmp/models/Qwen3-4B
modelscope download --model Qwen/Qwen3-8B   --local_dir /root/autodl-tmp/models/Qwen3-8B   # 抽查用

# ShareGPT
wget https://hf-mirror.com/datasets/anon8231489123/ShareGPT_Vicuna_unfiltered/resolve/main/ShareGPT_V3_unfiltered_cleaned_split.json \
  -O /root/autodl-tmp/datasets/ShareGPT_V3_unfiltered_cleaned_split.json

# 投机解码用的真实数据集（hf 数据集，走 HF_ENDPOINT）
#   likaixin/InstructCoder、philschmid/mt-bench
# GSM8K 由 lm-eval 自动下载，走 HF_ENDPOINT
```

旧基线用的是 `/root/autodl-tmp/huggingface/Qwen3-0.6B/`。新目录换成 `/root/autodl-tmp/models/`，复现旧数字时注意路径。

### 每次开机的固定动作

```bash
nvidia-smi                       # 确认 4090 D、显存空闲
source /etc/network_turbo        # 需要下载时
python tools/collect_env.py > results/v2/4090d/env.json   # 项目 A 里写一个这样的小脚本
tmux new -s bench
bash bench/run_matrix.sh ...     # 总控脚本
# 跑完
rsync / scp 把 results/ 拉回本地，或 git push
# 关机
```

## 三、远程 A3（910C）

### 先确认的信息（第 4 周第一天）

- [ ] 怎么登录：直连、跳板机、还是只能在公司网络里访问
- [ ] **能否访问外网**：能否 `docker pull quay.io/...`、能否访问 ModelScope / hf-mirror / GitHub / PyPI 镜像
- [ ] `npu-smi info`：芯片数、每个 die 的显存（A3 一台 8 卡、双 die 设计，系统里看到的是 16 个 `/dev/davinci*`）
- [ ] 驱动、固件、CANN 版本；是否已有 vllm-ascend 镜像
- [ ] 机器是独占还是共享。共享的话，跑之前用 `npu-smi info` 确认要用的 die 空闲，docker 只映射自己用的 `/dev/davinci*`
- [ ] 有没有可用的磁盘空间放模型权重（Qwen3-30B-A3B BF16 约 61GB，W8A8 约 31GB）

### 两种同步方式

**能联网**：

- 镜像：`quay.io/ascend/vllm-ascend:<版本>-a3`（国内可走 `m.daocloud.io/quay.io/ascend/...`）
- 模型：`VLLM_USE_MODELSCOPE=True` 或 `modelscope download`
- 代码：在 A3 上 `git clone` 项目 B 的仓库，本地改完 push，A3 上 pull

**不能联网**：

- 在能联网的机器上 `docker pull` 后 `docker save -o vllm-ascend-a3.tar`，通过公司允许的方式传过去 `docker load`
- 模型权重同样提前下好再传
- 代码打包成 tar 传过去；结果打包传回来
- 每次传输记下版本号，避免两边不一致

### 合规

- 只用**公开模型、公开数据集、开源代码**做项目 B，保证结论能在面试中公开讲。
- 不把公司内部的代码、配置、性能数据带出来。
- 如果 A3 是公司资源，先确认个人学习用途是否允许，以及对外讲实验数字有没有限制。

### 每次上机的固定动作

```bash
npu-smi info                                   # 确认空闲 die
docker start -ai vllm-ascend-env || docker run ...   # 见 03 文档
pip show vllm vllm-ascend torch torch_npu > env_versions.txt
cat /usr/local/Ascend/ascend-toolkit/latest/version.cfg 2>/dev/null   # CANN 版本，路径以实际安装为准
tmux new -s bench
bash scripts/run_matrix.sh ...
# 结果和 profiler 汇总带回；profiler 原始数据很大，只带分析后的汇总表和截图
```
